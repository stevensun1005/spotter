# 教练与学员

教练关系服务于计划分配与训练反馈：教练为学员安排训练，学员在自己的日历和原有训练页面执行。它使用独立的有方向关系，不会自动变为好友或搭子，也不会改变现有好友、饮食和搭子共享设置。同一账号可以有自己的学员，也可以接收其他教练的训练。

## 从邀请到训练

1. 教练创建限时的一次性邀请码，由本人分享给学员。学员登录本站，核对教练名称及共享说明后接受。
2. 教练从自己的单节计划、个人模板或训练周期准备训练，选择学员和日期，检查预览后发送。发送内容使用当时的快照，不把教练自己的私人模板链接交给学员。
3. 学员在教练入口查看收到的安排，核对动作和日期后确认接收。确认前不改变学员的训练日历；确认后使用现有逐组训练和打卡流程。
4. 教练查看自己下发训练的完成状态。实际组记录和反馈只按学员选择的共享范围返回，不获得学员的全部历史记录。
5. 任一方可以断开关系，后续分配、接收与反馈读取按当前有效关系重新校验。已经接收的计划和学员自己的训练历史保留。

接收前先查看对日历的影响，再按页面确认。进行中、已完成、已删除或学员手工修改的训练沿用现有保护规则。重复确认同一安排和网络重试不能生成重复日历计划。发送的是独立快照；教练之后修改自己的源计划不会自动覆盖学员内容。

## 账号和数据边界

- 教练和学员身份由当前登录账号与关系方向决定，不能由请求体传入任意 owner 替代。学员不能代教练发送，教练不能代学员接受，第三个账号不能读取关系或分配详情。
- 好友或搭子身份不授予教练权限；已有共享规则照旧。教练不获得学员其他教练分配的训练或无关私人训练。
- 原始心率、身体记录、体重、活动数据和饮食不属于教练功能的默认范围。训练的私人笔记与额外个人字段不能直接随整份 Session 返回。
- 学员关闭训练详情共享时，教练只能看允许的状态；受保护的原始数据、组记录及私人字段不出现在响应中。详情共享范围由学员控制。
- 「写给教练的反馈」是学员主动发送的独立内容，区别于训练记录里的私人笔记；关闭实际组记录共享不会撤回已经主动发送给该教练的反馈。断开关系后教练不能继续读取反馈。
- 跨账号读写在最终数据库操作时重新检查有效关系和对应分配。预览后关系断开、内容变化或已开始训练时，应拒绝或保护相关记录，不能以旧页面状态绕过检查。
- 周报和月报只统计本人已下发且获学员接收的打卡。详情共享开启时按实际打卡日期显示时长、组数和容量。关闭时按计划日期汇总完成状态。
- 课时由该关系中的教练登记，区分购课、扣课与冲销，每笔保留独立记录。重复提交只记一次，余额不足时拒绝扣课或冲销。断开后停止读取和登记该关系的课时。
- 邀请码、登录凭据和真实训练数据不进入 Git、URL 日志或错误日志；测试只使用临时数据库和合成账号。

## Sites 访问与当前发布范围

教练邀请只建立应用内关系，不能绕过私密 Sites 的平台访问控制。学员仍需先获得该私密站点既有访问权限，再登录并接受教练邀请。本功能不自动新增站点访客、修改站点可见性或扩大任何 Agent 令牌权限。

本轮在网页版源码与本地环境实现和验证，保存未部署版本；不部署正式 Sites、不改 iPhone App。正式站继续按用户约定等待动作库全部补齐并核对后统一更新。具体测试结果、构建提交和保存版本由本次交付说明记录，不能将本地验证当作生产账号的真实验收。

## 验证方式

`node --test tests/coaching-api.test.mjs` 使用 Node.js 24，直接导入生产 `/api/coaching` 路由，以 SQLite 模拟 D1 事务和三组合成平台身份。4 项测试覆盖未登录、同源检查、身份方向、好友不授教练权限、跨账号隔离、关联模板修改后的旧预览、确认幂等、详情共享投影、断开及重新连接不恢复旧授权。隐私样本使用明显的合成标记，确保私人笔记、额外个人字段、心率、身体与饮食数据没有出现在教练响应中。

本机生产 Worker 的 HTTP 验证脚本只在 loopback 地址模拟平台注入的身份 headers，用来检查实际 Worker 路由与本地 D1。它不代表已经通过真实 Sites 登录和外部学员授权；正式平台上的身份头仍由 Sites 可信边界负责。邀请和学员关系也不能代替站点访问授权。

完成本地构建和迁移后，运行 `npm start -- --port 8787`，再以 Node.js 24 运行 `node scripts/coaching-local-smoke.mjs http://127.0.0.1:8787`。它只接受本机 HTTP 地址，自动创建合成账号，检查实际 HTTP 邀请、源版本、接收、打卡、反馈与断开；邀请码只留在内存。可选 `--fixture` 会为开发预览的 `local_seedy` 准备合成教练/学员界面数据，不能用于正式账号。

当前工作台显示最近 100 份下发记录、最多 200 个活跃关系，来源选择器显示每类最近 100 项；旧数据仍保留。单个周期的训练内容不会因列表范围而被截断。教练本轮逐位选择学员下发，修改原计划不会自动批量更新既有副本。

## 公开功能参考

依据 Relay 的公开文档研究产品流程，独立实现 Spotter 的关系和权限边界，没有复制 Relay 代码、素材或私有算法。

- [邀请学员](https://www.relayathletic.com/docs/inviting-athletes)：独立邀请码与教练/学员角色。
- [单节分配](https://www.relayathletic.com/docs/assigning-single-workout)：为个人安排单次训练。
- [周期同步](https://www.relayathletic.com/docs/coaching-guide/program-assignment-and-sync)：变更预览，跳过个性修改，保护进行中与已完成训练。
- [学员体验](https://www.relayathletic.com/docs/athlete-experience)：执行训练并将实际训练结果反馈给教练。

本轮的学员确认与最小共享范围是贴合 Spotter 的设计，不代表 Relay 采用完全相同的授权流程。组织管理、收费、教练资质、消息和自动邮件不在当前模块中。

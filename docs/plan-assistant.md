# 添加计划：AI 起草与导入整合

原有重叠集中在入口和说明：导入页提供整理提示词，AI 连接页又提供计划接入说明，数据工具还生成一份训练写入说明。它们最终都使用同一套计划模型和编辑器，但用户需要在多个页面之间判断该选哪一个。

「添加计划」统一处理以下来源：

| 任务 | 入口与流程 |
| --- | --- |
| 已有文本、视频链接、计划 JSON 或文件 | 「粘贴已有内容」→ 预览和编辑 → 确认保存 |
| 用普通聊天 AI 起草或整理 | 「用自己的 AI」选择起草新计划／整理已有计划，复制提示词；把返回 JSON 粘贴到前一页预览 |
| 用站内 Claude 起草 | 从「设置 → AI 教练」生成草稿，送到同一计划预览，编辑后确认保存 |
| 已连接的 Agent 提交计划 | 同一页面查看 Agent 草稿，编辑、重新校验并确认入日历；连接和令牌管理收在 Agent 设置 |
| 完整多周周期文件 | 使用「训练周期 → 导入周期」，保留完整周期内容与周期自己的版本、预览和提交规则 |
| 训练记录和个人备份 | 使用「数据导出与导入 → 恢复备份」，不伪装成新的待训练计划 |

普通聊天 AI 和外部工具 Agent 继续使用用户自己的模型。站内 Claude 需要管理员在服务端开启，见 [AI 教练配置](ai-coach.md)。各入口的草稿都要经过预览和确认才会进入日历。

## 共用内容与保留边界

`features/import/ai-instructions.ts` 集中维护计划内容规则、通过实际 `planSchema` 生成的示例、普通聊天提示词和 Agent 计划接入说明。旧 `importPrompt()` 调用同一提示词；旧训练类别的 `createAgentGuide()` 复用同一套上下文→草稿→预览→确认指引。原有 REST/MCP 路由和兼容工具保持可用。

数据工具的可见 AI 说明只保留饮食、身体和模板，默认选饮食；训练引导跳到「添加计划」。这些数据类别不会自动混进计划起草提示词，也不会因为复制说明而获得新权限。

- 普通计划每批最多 20 堂；过量输入会明确拒绝，不截断。完整周期最多 52 周、364 节，继续走专用周期模型。
- 周期文件与备份文件会识别格式并显示对应入口，不再只报笼统的“JSON 有误”。
- 手动导入的同名更新须用户显式选择；Agent 草稿仍是私密追加、revision／有效期／账号校验流程，合并入口不合并它们的写入权限。
- 日期、动作库 ID、组别、器械站、次数范围、休息、节奏、kg/lb、目标 RPE 和用户明确提供的 1RM 参考沿用现有模型。未知重量保持 0，不把目标 RPE 当实际记录。
- 切换入口页签时保留粘贴内容和未保存预览；Agent 草稿与连接仍由原有账号接口读取。源文本改动后需重新预览，避免保存旧内容。
- 私密 Sites 的访问与 Agent 工具授权仍分别验证，个人连接令牌不会绕过平台门禁。

本轮只修改网页版源码，不部署正式 Sites、不改变站点访问权限或生产数据，也不改 App。实际构建提交、保存版本、浏览器检查及测试结果以本次交付报告为准。

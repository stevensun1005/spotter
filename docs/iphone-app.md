# 训练搭子 iPhone 原生 App

**Spotter** scheme 构建 SwiftUI 版 iPhone App，Bundle ID 为 `app.spotter.health`，支持 iOS 16 及以上。App 与 [Cloudflare 网页](https://spotter-free.couple-ledger-service.workers.dev) 通过 HTTPS 访问同一个账号和 D1 数据库。构建 10 是之前的网页壳版本，构建 11 起主界面由 SwiftUI 实现，构建 12 使用 Cloudflare 移动网页的配色、布局及项目资产。

## 使用与数据

- 登录后进入今日、训练、统计和好友四个原生标签页。底部四个标签使用网页的图标和半透明导航栏，右侧 AI 教练按钮打开可展开的对话面板。相机、照片、分享及账号授权使用 iOS 系统界面。
- Apple 登录通过 AuthenticationServices 验证，Google 使用系统授权窗口。访问码继续支持已有账号。到「设置 → 账号」可把另一个登录方式绑定到同一账号。会话保存在本设备 Keychain。
- 打开计划或自由训练后可以逐组记重量、次数和时长。计时按时间戳计算，可以跨前后台和锁屏。打卡重试沿用训练 ID，账号切换后分别读取各自的草稿。
- 统计使用 Swift Charts。「打卡历史」按月查看自己的训练和搭子已共享的打卡。点记录进详情，点日期查看当天的训练，自己的同日训练可以排序。今日页和训练页的「查看记录」也打开同一份训练详情。
- 自己的训练可编辑、另存为模板或生成图片分享卡。分享卡可切换样式、合并当天训练和隐藏明细。附带心率默认关闭。图片可以保存到照片或通过系统分享菜单发送。历史训练详情也可以按实际起止时间同步 Apple 健康心率。
- 体重可以读取并手动同步到账号。步数、活跃能量和系统运动时长可按日期在 App 查看。
- AI 面板支持文本对话、计划问答、草稿预览和保存，以及系统相机和照片选择器。确认识别的餐食后可以写入饮食记录。AI 请求继续走 Cloudflare 的权限和用量限制。
- 设置中的蛋白粉仓库可拍照在设备上读取标签，核对后保存配方并设为训练默认。完成训练时勾选喝过蛋白粉，会用同一笔打卡保存对应的饮食记录。
- 「设置 → 功能模块」开启「教练与学员入口」后，好友页的「找搭子」旁会显示教练入口。可邀请学员、下发计划和接收计划。
- 原生账号设置提供退出和删除账号。Google 需要 Cloudflare 具备 Google OAuth 配置才可发起真实授权。系统 Apple 授权、Apple Watch 来源和相机须用有对应权限的 iPhone 验收。

构建 40 的使用引导进入真实的训练、首页饮食和好友页面。浮层会高亮当前按钮，点按后继续。试填计划和记餐可以直接进入下一步，正式保存仍由用户操作。完成引导后，可打开 AI 教练选择训练目标，也可在「设置 → 关于与更新」重看引导。每日和每月的 AI 消息用量位于「设置 → AI 教练」，达到上限时对话区显示可重试的时间。

已在此设备验证的账号可以离线打开本机训练计划和草稿，打卡先保存到本机，联网后按原记录 ID 补传。器械配置、默认重量单位和休息时长在 App 与 Cloudflare 网页间同步。「设置 → 手表与健康」可选择是否为已上传的训练自动匹配 Apple 健康心率。App 会在前台补读最近七天的训练，并显示最近一次补读结果。好友可查看收到的加油，当前搭子可以提议、接受或取消训练邀约。

构建 24 的训练页可以撤销上一组，组间休息支持以 15 秒调整。缩小训练后，底栏上方显示训练进度和当前倒数，点一下即可返回。「设置 → 计时提醒」可以开启锁屏时的组间休息通知。饮食页可预览并复制往日指定餐次，已复制的食物在重试时跳过。打卡历史可点年月直接跳转，页脚显示打卡天数，并可一键回到本月。

构建 26 在逐组记录中显示上次实际重量与次数，可以沿用后继续编辑。动作进步页汇总近期训练和个人最好成绩。训练草稿与打卡详情分别显示本机保存、等待同步和已同步状态，暂时的连接错误会自动重试。今日页的待调整训练提供单堂或同周期顺延预览，确认后才修改日程。

饮食可以把已记的食物组合存为常用餐。组合保存在这台 iPhone，记入前可以选择份量、餐次和日期，保存后可撤销。实际饮食记录同步到账号。AI 教练的蛋白粉操作回执分别显示仓库、训练默认配方与各日期的饮食结果。

构建 27 起，首页收起饮食后只显示左上角的圆形图标，点按可恢复。iOS 26 及以上的训练、统计、动作库和饮食等页面使用系统液态玻璃控件。分段切换和成组按钮共用按压动效，并遵循减少动态效果设置。

构建 28 发送文字后会立即把它移入对话。照片记餐会记住当前这餐的描述和教练的追问，直接在同一对话中补充即可。可读的包装份量和用户明确填写的数量优先。「一碗粥」「一杯牛奶」等有合理依据的常见份量可直接估算并保存，回执显示估算依据，可编辑和撤销。

构建 29 在 App 运行期间保留 AI 教练对话，包含关闭面板和切到后台后返回。彻底退出 App 后，下次启动会开启新对话。已保存的训练和饮食继续出现在各自页面。页面中的筛选、按钮和卡片使用轻量按压反馈，液态玻璃用于顶部菜单与固定底栏。可以在底栏左右拖动切换标签，中央绿色按钮继续用于开始或打开训练。

## 训练中的 Apple Watch 心率

在已经配对的 Apple Watch 上安装「训练搭子」。iPhone 需运行 iOS 17 及以上，手表需运行 watchOS 10 及以上。在 iPhone 开始训练后，点计时器下方的「Apple Watch 心率 → 连接」。首次连接时，打开手表上的「训练搭子」，点「授权并开始」，在系统界面允许所需的健康权限。如果 iPhone 连接已超时，回到训练页点「重试」。

收到心率后，训练页显示当前 BPM。暂停时会清除读数，恢复后等待新样本。手表断连或超过 30 秒没有新样本时会隐藏旧读数。实时读数仅在配对设备之间传输。

手表保持连接时，在 iPhone 完成训练会读取这台手表的活跃热量、平均心率和已测得的静息热量。训练详情的「训练数据」卡将活跃与静息热量合计为总热量。缺少对应样本时，该项显示为「—」。手表连接晚于开始时间时，摘要只覆盖连接后的测量区间。摘要按当前账号及单堂训练保存，手表端的临时会话随后丢弃。详情的圆形同步按钮会在 Apple 健康查找该堂训练的心率曲线和相符的 Apple Watch 运动。

从构建 29 起，iPhone 开始训练并连接 Apple Watch 后，可以在表上看动作和组次、填写当前组、确认完成、暂停或继续，以及调整或跳过组间休息。表上操作同步到手机中的同一份训练草稿，结束训练和打卡仍在手机上完成。断开时手表保留上次显示的进度，重新连接后按手机的最新记录继续。

`npm run test:ios-app` 使用合成样本验证读数过滤、完训摘要传输、训练时段校验和热量计算。首次授权、实时 BPM、完训数据及断连后补传需在配对真机验证。

## 网页功能对照

按私密 Sites v78 的源码及 App 共用的 Cloudflare API 核对。以下覆盖训练、统计、社交和个人设置的主要入口。

| 功能 | SwiftUI 支持情况 |
| --- | --- |
| 今日、统计与训练详情 | 月历筛选、同日排序、计划和自由训练详情、记录编辑、另存模板、搭子近七天和加油。 |
| 训练分享 | 模板样式、肌群图、逐组明细、同日合并、选填心率、系统保存与分享。 |
| 计划导入 | 训练文本、B 站或 YouTube 跟练链接和 JSON 共用一个核对入口，从训练页、设置或 AI 教练进入。 |
| 外部 Agent | 在「设置 → 外部 Agent」为自己的工具创建可撤销的凭据，选定读写权限，再复制分析、计划或记餐指令。支持 MCP 和 REST。见 [接入说明](../cloudflare/docs/agent-api.md)。 |
| 训练周期 | 创建私人草稿、套用个人模板、编辑训练与阶段、复制周、调整起始日及周数、管理编排偏好、导入或导出周期 JSON、预览和确认排期。 |
| 计划与休息日 | 今日和训练页的计划菜单支持移动单堂、顺延同周期训练、查找下一个可训练日和删除计划。删除计划会保留已有打卡。 |
| 训练心率 | 在训练详情同步 Apple 健康心率。保持 Apple Watch 连接完成训练时，显示本次活跃热量、总热量及平均心率。WHOOP 在线授权与同步入口在网页。 |
| 外观 | 跟随系统、浅色和深色，青柠、薄荷、天空蓝和丁香紫强调色，以及文字大小和减少动态效果。外观偏好保存在本机。 |

## iPhone 小组件

登录 App 并加载训练后，长按主屏空白处，选择添加小组件并搜索「训练搭子」。小号显示下一堂课或当前训练，中号还显示本周打卡。点训练区域回到今日，有未完成的训练时直接继续。点中号的打卡入口打开打卡历史。

在锁屏编辑器中也可以添加圆形或矩形小组件。锁屏只显示训练状态和进度。App 在同步训练、完成打卡和回到前台时更新摘要，退出账号时清除摘要。

iOS 16.1 及以上开始训练时可显示锁屏实时活动，在支持的机型上也会显示于灵动岛。紧凑灵动岛显示训练计时和完成组数，展开后可查看下一组、休息倒计时与近期 Apple Watch 心率。点按回到训练。「设置 → 计时提醒 → 锁屏实时训练」可关闭。

## 构建

```sh
npm run build
npm test
npm run test:ios-app
npm run test:health-native
npm run ios:source-check
npm run ios:package
```

`ios:package` 在构建前后核对 `origin/main`、健康同步分支和 iPhone 开发分支，并核对 App 连接的 Cloudflare 提交。产物位于 `outputs/`，包括模拟器 ZIP 和构建清单。iPhone 安装使用 Xcode 签名或 TestFlight。

TestFlight 使用同一 **Spotter** scheme 的 Release 归档，分发目标是 App Store Connect 的 `app.spotter.health` 应用。主 App 的签名描述文件须支持 HealthKit、Sign in with Apple 和 Associated Domains。随 App 一起归档的 `app.spotter.health.watchkitapp` 也需要自己的 HealthKit 签名。Apple Developer 中的 App Group `group.app.spotter.health` 需分配给 `app.spotter.health` 和 `app.spotter.health.widget`。原生 Apple 服务端使用 `APPLE_OAUTH_NATIVE_CLIENT_ID=app.spotter.health`。网页的 Apple Services ID 与原生 App ID 在同一 Apple Developer 配置下管理，详情见 [登录配置](cloudflare-login.md)。

私密 Sites 与独立 Node 自托管服务各有账号和数据。配对码和批量健康同步协议另见 [健康设备同步](health-device-sync.md)。
